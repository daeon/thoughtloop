# Evidence ladder

Prefer evidence in roughly this order, while adapting to the domain.

## Software

1. Runtime behavior against the real requirement
2. Integration/end-to-end tests
3. Unit tests
4. Compiler/type checker
5. Static analyzers/security scanners
6. Repository invariants and authoritative documentation
7. Independent model review
8. Builder self-reflection

## Research / factual work

1. Primary source / original dataset
2. Official documentation or authoritative publication
3. Direct recalculation from raw data
4. Multiple independent high-quality secondary sources
5. Independent model review
6. Builder self-reflection

## Structured writing

1. Explicit user requirements
2. Source-grounded factual checks
3. Deterministic structure/length/format checks
4. Published style or terminology rules
5. Independent editorial review
6. Builder self-reflection

## Rule

If strong evidence conflicts with a model's assertion, trust the evidence unless there is a concrete reason the evidence itself is invalid.
