# Evidence ladder

Use the strongest practical evidence for the claim and domain. A useful default order is:

## Software

1. Real runtime or end-to-end behavior
2. Integration and focused tests
3. Compiler, type checker, and static/security checks
4. Repository specifications and authoritative documentation
5. Independent review
6. Model self-assessment

## Research and factual work

1. Primary source, original dataset, or direct calculation
2. Official or authoritative documentation
3. Independent high-quality sources
4. Independent review
5. Model self-assessment

## Structured writing

1. Explicit user requirements
2. Source-backed factual checks
3. Deterministic structure, terminology, and format checks
4. Applicable style rules
5. Independent editorial review

If strong evidence conflicts with a model assertion, trust the evidence unless there is a concrete reason it is invalid. Record what the evidence actually covers; unavailable evidence remains unknown.
